# 偏航 StepDrift

给大学数学基础课（高数、线代、概率论）作业与备考用的纯前端推导核查工具。
**不给答案，只指出「从第几步开始偏、偏在哪个概念上」。**

## 运行

双击 `index.html` 即可。零构建、零后端、零外部 CDN、零第三方库（公式为自写 LaTeX 降级排版）。
所有判定在本机完成；错因归档存 `localStorage`（key：`stepdrift.archive.v1`），无需登录。
图片只在本机内存里显示（`URL.createObjectURL`），不写入存储、不送往任何服务。

## 两种输入方式

左栏输入区顶部有两个标签：

- **文字输入**：原有方式，直接粘贴或上传 `.txt` 推导。
- **图片对照**：左边放一张手写推导图片（上传或拖拽，点击缩略图可放大），右边是对照图片录入的 LaTeX 文本框；文本框下方必须勾选
  「我已逐行核对：文字与图片中的推导一致」，`开始判定` 才解锁。未勾选时按钮为灰态且提示「请先核对图片与文字是否一致」。

约定：

- 图片只是对照物，判定入口始终是一框**已由用户确认**的文字；`SD.engine.analyze(text)` 的接口没有变化。
- 勾上之后再次改动文本或换一张图片，勾选自动失效，需重新核对——避免确认过的内容与送去判定的内容不是同一份。
- 工具不会因为图片内容而改动、修正你录入的文字：录错了符号，判定的就是那串错文字。
- 点样例或上传 `.txt` 会切回「文字输入」标签，行为与以前一致。

## 判定边界（与页面「判定边界」弹窗一致）

**覆盖**
- 代数等价：固定种子 12 点抽样，仅对纯算术表达式（含 `+ - * / ^`、括号、隐式乘法、sin/cos/tan/ln/exp/sqrt/abs、pi、e）。
- 极限声称：识别 `lim(x→a)` 与 `x→∞`，左右各 6 点（h=1e-1…1e-6），核验双侧存在性、相等性与声称值。
- 五类概念规则：连续⇒可导方向反转 / 洛必达前提未验证 / 导数之比无极限⇒原极限不存在 / A 不可逆⇒无解 / 「恰有一人」写成 A∪B。
  触发条件带方向与前提识别，正确的推导不会被误判：
  - 「可导 ⇒ 连续」（条件侧是可导）不判错；只抓「连续 ⇒ 可导」。
  - 「由洛必达法则」且本步写出的极限抽样收敛（如 `lim(x→0) sin x/x = 1`）不判存疑；只有导数之比抽样不收敛时才记「前提未验证」。
  - 「恰有一人」写成 `(A∩B̄)∪(Ā∩B)` 这类含补事件的互斥分解不判错；只有直接写成 `A∪B` 时才判。
- 结论冲突：同链「无解 ⇄ 无穷多解」单独出卡。

**不覆盖**
- 矩阵、事件等对象表达式的具体计算（rank 求解、行列式求值等），出现时跳过数值判定，避免误判。
- 几何证明、积分技巧、多变量与抽象证明。
- 题意理解、最终答案是否算完。

**「未判定」的含义**：未命中任何可复核规则 → 没有证据下结论，标灰而不是标绿。未判定 ≠ 正确。
「受上游影响」：该步引用了已判定不成立的结论，不单独计错。

## 规则库：怎么加一条
打开 `js/rules.js`，向 `SD.rules.list` 追加一个对象：

```js
{
  id: 'R-MY-RULE',                 // 唯一 id，会显示在该步核查记录里
  tag: '充分必要条件混淆',          // 必须是 archive.js 中 CATEGORIES 的 7 类之一（新类别需同步添加）
  when: function (step, ctx) {     // 触发条件：step.raw 原文 / step.formulas 公式数组
    return step.raw.indexOf('某关键词') !== -1;
  },
  build: function (step, ctx) {    // 命中后生成判定与卡片，文案写死在本文件，可复核
    return {
      status: 'fail',              // fail 不成立 / doubt 存疑
      tag: '充分必要条件混淆',
      card: {
        title: '一句话说清错在哪里',
        diagnosis: '一句诊断',
        gap: '缺的条件（高亮块）',
        evidence: ['证据行：必须有具体数字或具体方向判断'],
        theorem: {
          core: '定理核心',
          conditions: ['需要同时满足的条件 1', '条件 2'],
          counterexample: '反例',
          fix: '怎么修'
        }
      }
    };
  }
}
```

引擎按 `list` 顺序先命中先判；概念规则优先于极限/等价检查。
`when` 不要只匹配关键词：要区分条件侧与结论侧（蕴含方向），并在能用抽样确认前提成立时放行，否则正确的推导会被误判成偏航。
`ctx` 提供：`allSteps`、`prevExpr`、`hasLhopital`、`originalLimit`、`fDef`、`extractLimitBody(step)`、`findRankA()`、`findRankAb()`。
数值证据请通过 `SD.sampling`（`analyzeLimit` / `checkEquivalence` / `oscillationRange`）生成，不要写死无法复现的数字。
若后续接入 LLM，只允许改写 `build` 返回文案的措辞，不允许改 `status` 与判定结论。

## 验收样例在哪

- 样例文本：`js/samples.js`（A 连续与可导 / B 洛必达失效 / C 秩与解结构 / D 恰有一人 / E 变形不守恒）。
- 一键触发：页面左栏样例 chips，或空状态「用样例跑一遍」（= 样例 A）。
- 期望输出速查（与 `node selftest.js` 打印一致）：

| 样例 | 步骤状态 | 偏航卡 |
| --- | --- | --- |
| A | 未判定 / 通过 / **不成立** / **不成立** / 受上游影响 | 01 第3步·充分必要条件混淆（缺：导数定义式双侧极限存在性；反例 f(x)=\|x\|）；02 第4步·存在性判据缺失（左极限≈-1，右极限≈1）。摘要：从第 3 步开始偏航，2 处结论级问题 |
| B | 通过（趋于 1）/ 存疑 / 不成立 | 01 第2步·定理适用条件未验证；02 第3步·充分必要条件混淆（导数之比抽样 0.0006~1.9 摆动，原极限趋于 1，失效≠不存在） |
| C | 通过 / 不成立 / 未判定 / 通过（判据链完整） | 01 第2步·解结构判据缺失；02 第2步⇄第4步·推理链自相矛盾 |
| D | 未判定 / 通过 / 不成立 / 受上游影响 | 01 第3步·事件与对象语义误读（正确分解=0.5，0.8−0.5=0.3=P(A∩B)；算术没错，错在事件先被认错了） |
| E | 未判定 / 通过 / 不成立 / 通过 | 01 第2步→第3步·变形不守恒（x=2 时两边 3 与 0.333，差 2.667） |
